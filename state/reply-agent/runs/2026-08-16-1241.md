## Incident: state was written but never pushed

The scheduled session sent both messages, then failed to push its commit:

```
remote: access denied by the git proxy: rifqiraka234-oss/astra-agency is not
in this session's authorized repository set
```

The container held the only copy of the checkpoint and audit line. Origin
still showed an empty checkpoint and a zero byte `auto_sent.jsonl`, so the
next run would have treated all 46 conversations as unseen and could have
messaged Kenfack and Basile a second time.

**Root cause is ordering, not the proxy.** The run performed an irreversible
external action before establishing that it could record that action. The
403 was the trigger; the design flaw is that a send was possible at all
while recording was not.

**Fix applied:** the playbook now opens with a push-access preflight
(`add_repo` with `access: "push"`, then `git push --dry-run`). A run that
cannot push switches to queue-only and sends nothing. This mirrors the
enrichment pipeline's persist-before-import rule, which exists for exactly
the same reason.

**Recovery:** checkpoint and audit trail rebuilt from Lemlist and pushed from
an operator session that does hold write credentials. No duplicate messages
were sent.
